PlantPal

Ein self-hosted, einladungsbasierter Pflanzen-Gieß-Tracker im Pokédex-Stil. Jede Pflanze ist ein Sammelkarten-Eintrag — mit Foto, Gieß-Intervall und abgestuftem Durst-Status. Diese Doku erklärt, wie das System aufgebaut ist und warum — ohne im Code zu versinken.

Frontend · React + TypeScript PWA Backend · FastAPI + SQLite Deploy · Docker + Cloudflare Tunnel Privacy · 100 % lokal (außer E-Mail)

01 Überblick

PlantPal hilft mehreren Haushalts-Nutzern, ihre Zimmerpflanzen rechtzeitig zu gießen. Statt einer nüchternen To-do-Liste ist jede Pflanze ein „Plantdex"-Eintrag mit pixeligem Foto. Wer Zugang will, braucht einen Einladungs-Link — es gibt keine offene Registrierung.

🪴 Plantdex

Pflanzen anlegen, fotografieren, bearbeiten. Sortier-, Filter- und Suchfunktion.

💧 Gieß-Tracking

Ein Tipp markiert „gegossen". Eine Historie merkt sich jeden Gieß-Vorgang.

📊 Statistik

Gieß-Streak, Konsistenz, „am längsten überfällig", Durchschnitts-Intervalle.

✉️ Erinnerungen

Tägliche E-Mail-Digest zur selbst gewählten Uhrzeit, wenn Pflanzen durstig sind.

🎟️ Einladungen

Jeder Nutzer hat ein Einladungs-Kontingent und erstellt Mehrfach-Links.

📦 DSGVO-Export

Jeder kann alle eigenen Daten als ZIP exportieren — inklusive Fotos.

Designprinzip: klein und wartbar. Eine flache Modul-Struktur, eine einzige SQLite-Datei, keine externe Abhängigkeit außer einem E-Mail-Versender. Läuft auf einem Raspberry Pi genauso wie in der Cloud.

02 System-Architektur

Vier Bausteine: die installierbare Web-App im Browser, ein verschlüsselter Cloudflare-Tunnel als Eingangstür, der FastAPI-Server mit seiner SQLite-Datenbank, und ein externer E-Mail-Dienst. Es sind keine Ports nach außen offen — der Tunnel verbindet sich von innen heraus.

03 Technologie-Stack

Bewusst schlank gewählt: etablierte Bausteine, wenig Magie, alles typisiert.

🎨 Frontend

React 18 + TypeScript · Vite-Build · Tailwind v4 (Design-Tokens) · TanStack Query (Server-State & Caching) · React Router · sonner (Toasts) · eigene, abhängigkeitsfreie i18n (DE/EN) · manuelle PWA (Manifest + Service Worker).

⚙️ Backend

Python 3.12 + FastAPI · aiosqlite mit rohem, parametrisiertem SQL · Pydantic v2 (zugleich DB-Mapping & API-Schema) · APScheduler (stündlicher Cron) · Pillow (Bild-Pipeline) · structlog.

🗄️ Daten & Persistenz

SQLite (WAL) · nummerierte SQL-Migrationen in einer _migrations-Tabelle · Soft-Delete · pro-Request-Verbindung für Transaktions-Isolation · Berlin-Zeitzone, tag-genaue Logik.

🚀 Betrieb

Docker Compose · Cloudflare Tunnel (kein offener Port) · Resend für E-Mails · SQLite-Backups (Script / optionales Litestream-Profil) · health-Endpoint für Monitoring (z. B. UptimeRobot).

04 Lebenszyklus eines Requests

Jeder API-Aufruf durchläuft dieselben Schichten. Der Service-Worker lässt private /api- und /auth-Anfragen bewusst ungecacht durch; der Server prüft Herkunft, CSRF und Rate-Limit, bevor die eigentliche Logik läuft.

Warum eine Verbindung pro Request? SQLite teilt sonst eine Transaktion über parallele Anfragen — ein Rollback der einen könnte Schreibvorgänge einer anderen rückgängig machen. Eine frische Verbindung je Request isoliert das sauber.

05 Authentifizierung & Einladungen

Passwortlos und einladungsbasiert. Zum Einloggen kommen zwei gleichwertige Wege per E-Mail an: ein Magic-Link zum Klicken und ein 6-stelliger Code zum Eintippen. Beide teilen denselben einmaligen Token.

🔗 Multi-Use-Links

Ein Invite kann mehrfach nutzbar sein; ein Kontingent pro Nutzer verhindert unbegrenztes Einladen. Wer wen eingeladen hat, ist nachvollziehbar.

🔁 Session-Erneuerung

Aktive Sessions verlängern sich automatisch (Soft-Cap 90 Tage, Hard-Cap 180), ohne erneuten Login — bequem und trotzdem begrenzt.

📧 E-Mail-Wechsel

Bestätigung an der neuen Adresse plus Hinweis an die alte; eine Race-sichere Eindeutigkeitsprüfung verhindert Duplikate.

06 Datenmodell

Alles hängt an users. Pflanzen und ihre Gieß-Historie, Sessions, Login-Tokens und Einladungen verweisen per Fremdschlüssel zurück — Löschen kaskadiert sauber.

Tabelle Zweck Besonderheit

07 Features im Detail

Abgestufter Durst-Status

Statt eines binären „durstig / nicht durstig" zeigt jede Karte einen von vier Zuständen. Das Backend liefert tag-genau in Berlin-Zeit, ob eine Pflanze durstig ist und um wie viele Tage sie überfällig ist; das Frontend leitet daraus die vier Anzeige-Stufen ab:

● Aktuell

Noch ≥ 2 Tage Zeit. Dezenter grüner Punkt.

● Bald fällig

Morgen dran (noch ein Tag Puffer). Gelber Tropfen.

● Fällig

Heute fällig bis 3 Tage drüber. Oranger Badge mit Tageszahl.

● Stark überfällig

4+ Tage drüber. Roter Badge — dringend gießen.

Erinnerungen ohne Doppel-Mail

Ein stündlicher Cron prüft, welche Nutzer ihre gewählte Erinnerungs-Stunde erreicht haben und durstige Pflanzen besitzen. Eine doppelte Absicherung (reminder_send_log + Datums-Markierung) garantiert höchstens eine Mail pro Tag — selbst über die Sommerzeit-Umstellung oder nach einem Neustart.

Bilder als Pixel-Kunst

Hochgeladene Fotos werden serverseitig quadratisch zugeschnitten, auf 96 × 96 Pixel verkleinert und per CSS pixelig gerendert — der charakteristische Retro-Look, ganz ohne große Dateien.

08 Sicherheits- & Privacy-Modell

Das System ist für genau diese Angriffsfläche gebaut — von zwei unabhängigen Reviews (KI-Agenten + externes Modell) bestätigt: keine kritischen Lücken.

🔐 Geheimnisse

Tokens, Codes und Sessions liegen nur als gepfefferter HMAC-SHA256 in der DB. Klartext existiert ausschließlich im Link bzw. Cookie des Nutzers.

🛂 Zugriffs-Isolation

Jede Abfrage ist an die Nutzer-ID der Session gebunden. Niemand kann fremde Pflanzen, Bilder, Einladungen oder Statistiken sehen (kein IDOR).

🎫 CSRF

Double-Submit-Cookie plus X-CSRF-Token-Header auf allen schreibenden Anfragen, dazu ein exakter Origin-Abgleich.

⏱️ Rate-Limiting

Login, Code-Prüfung, Registrierung, Einladungen, E-Mail-Wechsel, Upload und Export sind gedrosselt — pro IP, E-Mail (gehasht) und Nutzer.

🖼️ Upload-Härtung

Magic-Byte-Prüfung statt Dateiendung, Schutz vor Dekompressions-Bomben, Metadaten-Entfernung, traversal-sichere Pfade, abgebrochen vor dem Vollpuffern.

🔒 Privacy / lokal

Keine Telemetrie, keine CDNs — Schriften sind selbst gehostet. Einzige externe Verbindung ist der E-Mail-Versand. DSGVO-Export ohne jegliche Geheimnisse.

Zwei-Reviewer-Prinzip: Spezialisierte Agenten und ein unabhängiges Drittmodell prüfen jeden Meilenstein. Gefundene Punkte (z. B. ein Lockout-Off-by-one oder ein Upload-Speicher-Limit) wurden behoben und mit Tests abgesichert.

09 Betrieb & Deployment

Ein docker compose up startet den Server und den Cloudflare-Tunnel. Es muss kein Port in der Fritzbox geöffnet werden — der Tunnel baut die Verbindung von innen auf, TLS endet bei Cloudflare.

🐳 Container

Ein App-Container (FastAPI + gebautes Frontend) + ein cloudflared-Container.

💾 Backups

Konsistente SQLite-Kopie per Python-Backup-API; optionales Off-Site-Replikat (Litestream-Profil).

❤️ Health

/api/health meldet DB-Schreibbarkeit, WAL-Modus und Cron-Jobs — ideal für UptimeRobot.

Skaliert mit: SQLite + ein Prozess reichen für einen Haushalt oder kleinen Freundeskreis locker. Wächst der Bedarf, sind die natürlichen nächsten Schritte ein Litestream-Replikat und eine Aufteilung der Routen-Datei.
